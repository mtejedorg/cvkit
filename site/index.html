A CV tailor that is not allowed to lie.

cv-builder turns a job posting and a fact file about you into a tailored CV, cover letter and project portfolio. It stops and asks when the posting wants something your file doesn't back up, then reviews, scores and verifies its own work before handing it over.

Design philosophy

Six rules the whole skill is built around

AI-written applications tend to fail in two ways: they invent things, and they sound like every other AI-written application. Each rule below targets one of those failures, or the checks that catch them.

01

No hallucination

Every skill, title and number must exist in the candidate profile. If the posting needs something the profile lacks, the skill halts and asks you instead of assuming.

02

Humanized, not detector-evasion

A direct rewrite pass removes template-sounding language while keeping every fact identical. No translation chains, no external APIs, no attempt to hide that AI was used.

03

Fresh-context review

A second agent with no memory of the drafting critiques the result against the posting, so it catches missed keywords and weak framing the drafter has stopped seeing.

04

Verified PDFs

Every PDF is checked for page count, a clean text layer and literal contact details, so an applicant tracking system can actually read it. Then it is inspected by eye.

05

The profile learns

Every answer you give to a clarification question is written back to your profile in your own words. A "no" is kept as a confirmed gap, so it is never claimed later and each application starts from better facts than the last.

06

Lead with proof

The profile ranks your strongest verifiable claims and names a positioning profile per kind of role. Each run picks three proof points for the posting and puts them in the summary, the first bullets and the letter's opening, within a two-page budget.

How it works

Draft, humanize, review, score, compile, verify

The skill runs these phases in order. The red and green tags mark where it stops for you or checks itself.

  1. 0

    Workspace

    Finds your private workspace (profile, applications, log) through an environment variable or a gitignored config file, so the public skill repo never holds a personal file.

  2. 1

    JD analysis, fit check & clarification Halts & asks you

    Saves the posting as JD.md, reads it against your candidate profile and rates the fit (location, permit, seniority, domain years, language). If the fit looks unlikely it says why and asks before going on.

    It then cross-references the posting with your profile. Every item the profile doesn't back, hard requirement or soft skill, is a question for you, asked before a single word is drafted. Then it names the positioning profile and the three proof points it will lead with.

  3. 2

    Drafting

    Writes the CV, cover letter and project portfolio in Markdown, then self-critiques for truthfulness, bullet order and structure. No PDF yet: compilation happens once, at the end.

  4. 3

    Humanization pass Facts frozen

    Rewrites for natural variation against a checklist. Style only: no fact, number, date or meaning may change.

  5. 4

    Reviewer subagent Fresh eyes

    A subagent with a clean context gets the posting, the drafts and the relevant profile excerpt, and returns a structured critique. Its feedback is applied, and the humanization check is re-run on anything it changed.

  6. 5

    Gates & score 2 gates + 0–100

    Two pass/fail gates (format, truth), then a score where half the points are evidence: how many of the posting's must-haves your profile backs and the CV shows. An invented claim found here sends the run back to phase 1, not into a quiet deletion.

  7. 6

    Compile & verify PDFs Automated + visual

    Renders the Markdown onto real A4 pages (two for a CV, one for a letter), builds a phone-less public variant on request, runs the verifier, and reads the result to confirm nothing is cut off or misaligned.

  8. 7

    State update Writes your profile

    Every answer you gave, from phase 1 or from questions the reviewer or scoring raised later, is saved to the candidate profile in your own words. A "no" goes under Confirmed gaps. Nothing is inferred, and the exact lines added are shown to you. This runs even after short commands like an ATS-only check.

  9. 8

    Interview prep Optional

    On request, a STAR-method prep pass based on the posting and the final documents.

Rules 01 & 05 in action

Ask before lying, then remember the answer

When the posting asks for something the profile doesn't contain, the skill does not stretch the truth. It stops, asks, and keeps what you told it.

Rule 02 in action

Humanizing means "don't sound like a template"

The pass changes how a true sentence is said, never what it says.

What the pass looks for

  • Banned stock phrases ("proven track record", "seamless", "leverage" as a verb…)
  • Consecutive bullets opening with the same verb
  • Every sentence the same length and shape
  • More than one "moreover / furthermore / additionally"
  • Em-dash overuse
  • No fact, number, date or title changed
Why not a detector-evasion pipeline? Some humanizer tools push text through chains of machine translation to fool AI-content detectors. That was rejected here: nobody scans a CV for detector signals (a recruiter or a text parser reads it), and every extra translation hop risks drifting a tool name, a metric or a date in a document where each claim must stay true. This skill never tries to hide that AI helped.
Rules 03 & scoring

A second opinion, and a score with a penalty

The reviewer gets, inline

  • The job posting, verbatim
  • The drafted CV, cover letter and portfolio
  • Only the profile sections relevant to this posting
  • The ATS score, if already computed

The reviewer returns

  • Keywords the profile supports but the draft missed
  • True claims stated too vaguely
  • Language that still reads as templated
  • The same metric phrased two different ways across documents

The reviewer is told it is reviewing, not researching the company or inventing anything about the candidate. Suggesting a claim the profile lacks is treated like any other gap: it goes back to you as a question.

Evidence coverage: each ranked must-have counts when the profile backs it and the CV shows it with evidence.
Placement: the three leading proof points in the summary and first bullets.
Content quality: action + what + how + measurable result, checked against the profile.
Keywords: real posting terms the profile supports. Gaps are acknowledged, never stuffed.
Truth gate: one invented skill or claim, or one assumed without asking, fails the run: it goes back to phase 1 and asks you. The format gate (single column, standard headings, order, length) is pass/fail too.
Rule 04 in action

Output that is checked, not assumed

Below is a real PDF compiled and verified by the toolchain. The fictional candidate's Markdown was written by hand for this page, so it shows the output stage, not the drafting.

  1. Markdown → HTML with a fixed template (single column, standard font, a flexbox header).
  2. Headless Edge → PDF on real A4 pages, with break rules that keep a role title with its first bullets. A --public build strips the phone number for anything that goes online.
  3. Verifier enforces the page cap (two for a CV, one for a letter), checks the text layer for garbled characters, that the sections appear in order, and that the contact details are literal text (or, for a public build, that the phone is absent).
  4. Privacy check scans every tracked file for the candidate's own patterns before a commit can land.
  5. Visual read confirms nothing is cut off and the header renders as a proper row.
Use it

Run it for yourself

It is designed to be forked and used by any candidate, not just the author.

  1. Fork or clone the repo and install the dependencies: Python 3.10+, pip install PyMuPDF markdown, and Microsoft Edge for headless PDF rendering.
  2. Write your candidate profile in _private/candidate_profile_<your-name>.md: experience, skills, education, positioning, deal-breakers and STAR stories. This file is the only thing the skill is allowed to believe.
  3. Open Claude Code in the folder and ask: "Tailor my CV for <posting URL or pasted text>".
  4. Answer the questions it asks about gaps. It will not draft until you do, and it saves your answers to the profile afterwards so it doesn't ask twice.
  5. Collect the results in _generated/<Company>/. Both _private/ and _generated/ are gitignored, so your personal data never reaches version control.
Transparency

What it does not do

  • It is AI-assisted writing. The drafting is done by a language model, and it can still make mistakes. The profile gate, reviewer and scoring reduce that risk but do not remove it, so read every document before it goes out.
  • It is only as honest as your profile. The skill trusts the fact file. If the file overstates something, the output will too. Because your answers are written back to it, a wrong answer persists until you correct it, which is why the skill shows you each change.
  • The score and the fit verdict are heuristics. They catch problems and flag likely screens (location, permit, seniority), but they are not a measurement from any real applicant tracking system. Each application's score and outcome are logged so you can check whether they predicted anything.
  • Humanizing is not concealment. It exists so the text reads like a person wrote it, not to disguise AI involvement.
  • Tested on Windows. PDF rendering needs Microsoft Edge. The script looks for it at standard macOS and Linux paths too, but that is untested.
  • No guarantees. A well-tailored, truthful CV helps. It does not get you an interview on its own.
